# MedGraph AI Data Model

Version: 1.0 (Frozen)

---

# Purpose

This document defines the logical data model used throughout MedGraph AI.

It specifies:

- Healthcare entities
- Relationships
- Data ownership
- Storage locations
- Data flow

This document does **not** define implementation details such as Cypher queries or SQL schemas.

---

# Data Architecture

MedGraph AI stores different categories of data in different systems.

| Data Type | Storage |
|------------|----------|
| Healthcare Relationships | Neo4j |
| Clinical Guidelines | Qdrant |
| ML Features | Feature Table (Generated by PySpark) |
| Trained Models | Serialized Model File |

Each storage system has a single responsibility.

---

# Healthcare Entities

The Healthcare Knowledge Graph consists of eight core entities.

## Patient

Represents an individual synthetic patient.

Attributes

- Patient ID
- Name
- Gender
- Birth Date
- Marital Status
- Race
- Ethnicity
- Address
- City
- State

---

## Encounter

Represents a healthcare visit.

Attributes

- Encounter ID
- Start Time
- End Time
- Encounter Type
- Organization
- Provider

---

## Condition

Represents a diagnosed medical condition.

Attributes

- ICD Code
- Disease Name
- Diagnosis Date
- Clinical Status

---

## Medication

Represents prescribed medication.

Attributes

- RxNorm Code
- Medication Name
- Start Date
- Stop Date

---

## Observation

Represents laboratory measurements or clinical observations.

Examples

- HbA1c
- Blood Pressure
- BMI
- Heart Rate
- Glucose

Attributes

- Observation Type
- Value
- Unit
- Date

---

## Procedure

Represents a performed medical procedure.

Attributes

- Procedure Code
- Procedure Name
- Date

---

## Provider

Represents the healthcare professional.

Attributes

- Provider ID
- Name
- Specialty

---

## Organization

Represents the healthcare institution.

Attributes

- Organization ID
- Name
- Address

# Why Encounter Is the Central Node

Healthcare naturally revolves around visits.

Instead of connecting everything directly to the patient,

Patient

↓

Encounter

↓

Everything Else

creates a chronological patient journey.

Benefits

- Timeline reconstruction
- Cleaner graph traversal
- Better visualization
- Easier temporal analytics

---

# Feature Engineering Dataset

Machine Learning does NOT directly query Neo4j.

Instead,

PySpark generates a structured feature table.

Example Features

- Age
- Number of encounters
- Number of chronic conditions
- Number of medications
- Number of procedures
- Average BMI
- Latest HbA1c
- Latest Blood Pressure
- Latest Glucose
- Chronic disease count

This table becomes the training dataset.

---

# High-Risk Classification Target

The ML model predicts whether a patient belongs to a high-risk cohort.

Risk is derived from synthetic healthcare history.

The prediction is used only for educational analytics.

# Clinical Guideline Storage

Clinical guidelines are stored independently.

Workflow

PDF

↓

Chunking

↓

Embedding

↓

Qdrant

Each chunk stores

- Text
- Source Guideline
- Page Number
- Embedding Vector

No patient information is stored in Qdrant.

# Data Integrity Rules

Every Patient must have

- at least one Encounter

Every Condition belongs to

- one Encounter

Every Medication belongs to

- one Encounter

Every Observation belongs to

- one Encounter

Every Procedure belongs to

- one Encounter

Every Provider belongs to

- one Organization

These constraints ensure graph consistency.

# Summary

The MedGraph AI data model separates healthcare relationships, machine learning features, and clinical knowledge into dedicated storage systems.

This separation improves scalability, maintainability, and ensures each technology is responsible for exactly one category of data.
